OrderStatusWhenNext step shown
1Needs your decisionA run is waiting at the final decision. The newest one counts; older waiting runs of the company are "superseded" and don't count.Decide
2Needs plan approvalA run is waiting at the plan gate.Review the plan
3ResearchingA run is queued or running (including a report being rewritten after "send back").Watch progress
4Decided: tracking etc.Your latest decision, when no newer run is waiting or running. Shows the verdict.Open memo
5CompletedThe latest finished run was exported with no decision recorded (older runs), and nothing above applies.Open memo
6StoppedThe latest run failed or was cancelled and nothing above applies.See what happened
7Not startedNo runs. Companies with only test runs are hidden unless you show them.Start research

The first rule that applies wins. A newer stopped run never hides a waiting report or a decision; it's mentioned beside the status ("Decided: tracking · a later run stopped"). Home, the Research list, Reviews and the nav badge all use this one function.

Back-end work these designs need

  • The status function above, returned per company by the overview endpoint (with its waiting run, plan-gate run and progress), plus filter counts and paging for the Research list. The review queue gets paging too (it stops at 50 today).
  • Cost totals per company (all time) and per month, summed from each run's recorded cost.
  • A "dismissed" marker so a dismissed report reads "Dismissed", not "Failed", in its memo. Interim shortcut: the cancel action already writes "Cancelled by <actor>", so dismissing could pass actor "dismiss"; the proper design is a stored marker, like the stop reason.
  • The review queue returns the allowed approvals from the same checks the route runs: tracking = the review gate's "trackable"; position = "positionable" and the report's conclusion not withheld. The gate also returns a code per blocking reason so the page can show plain sentences.
  • Any decision on the newest report (including "send back", which rewrites that same run) dismisses the company's older waiting runs in the same transaction, so superseded versions never resurface.
  • Cost hints count only runs on the current model setup (stored per model call): the September SoFi runs used DeepSeek and cost far less than the November runs on Claude Haiku. Reader copy says "a cheaper setup" and never names models.
  • A stored stop reason for failed runs (budget, error, cancelled) instead of reading the failure text.
  • Dismissing an older version reuses the cancel action, with a check that refuses the newest waiting run.
  • Plain-language "what this means for you" lines per AI finding would need the reviewer to write them pipeline change, optional
  • Resuming a stopped run from the failed step not proposed: the designs offer "start over" with a confirmed budget.
